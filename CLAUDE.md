# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

CV Builder: a React 19 + TypeScript + Vite app (MUI v7, Redux Toolkit) with a split view — an editor on the left and a live A4 preview on the right, exportable to PDF — plus a small local Fastify server that stores the data as JSON files. See the GitHub issues #28-#49 for the roadmap (phases 0-1 done).

## Layout

One package, three folders in `src/`:

- `src/web` — the React app (components, hooks, pages, Redux store, styles). Entry: `src/web/main.tsx`.
- `src/server` — the local API (Node, Fastify). Entry: `src/server/main.ts`.
- `src/shared` — code both sides import: the `runtypes` schemas (`shared/custom-types`) and the pure vault logic (`shared/vault`: migration, file format, helpers). Keep it free of React, Redux and Node APIs.

## Commands

Package manager is **pnpm**.

- `pnpm dev` — web (Vite, :5173) and server (:3001) together; Vite proxies `/api` to the server. `pnpm dev:web` / `pnpm dev:server` run one of them; `pnpm server` runs the server once, without watching. `PORT`, `DATA_DIR` (default `./data`) and `WEB_URL` (default `http://localhost:5173`, must be this machine) configure the server. PDF export needs Chromium once: `pnpm exec playwright install chromium` (downloads ~110 MB to the Playwright cache, not the repo) and the web app running at `WEB_URL`.
- `pnpm build` — `tsc -b && vite build`
- `pnpm test` — Vitest (once); `pnpm test:watch`. Single file: `pnpm exec vitest run src/path/file.test.ts`. Tests live next to the code as `*.test.ts(x)`. Default environment is node; component tests start with `// @vitest-environment jsdom` and use Testing Library (see `pages/editor-page/editors.test.tsx`). jsdom is pinned to v26 because newer versions need a newer Node than some machines here have.
- `pnpm test:e2e` — real-browser tests in `src/e2e/*.e2e.ts` (separate Vitest config, not part of `pnpm test`): they start the API on a temp data folder, Vite and Chromium; `pdf.e2e.ts` checks PDFs (page count, A4, text layer via `unpdf`, hidden/ordered content) and `editor.e2e.ts` drives the UI (hide an item, keyboard-reorder a section, save, export PDF, reload). Needs `pnpm exec playwright install chromium` once; CI does it. Use these for anything about real layout, which jsdom cannot show (they already caught a page-count rounding bug).
- `pnpm lint:check` — ESLint on `src`, no changes (what CI runs); `pnpm lint` does the same with `--fix`
- CI (`.github/workflows/ci.yml`) runs build, lint:check, format-check and test on every PR.
- `pnpm format-check` / `pnpm format-fix` — Prettier (`.prettierrc`: `trailingComma: es5`; keep that style)

## Architecture

**Path aliases are mandatory.** ESLint (`no-restricted-imports`) forbids relative imports (`./`, `../`). Use `@components/*`, `@custom-styles/*`, `@hooks/*`, `@pages/*`, `@store/*` (all under `src/web`), `@shared/*`, `@custom-types/*` (`src/shared/custom-types`), `@server/*`, `@fixtures/*`, `@e2e/*` (`src/e2e`) (defined in `tsconfig.json`, resolved by `vite-tsconfig-paths`). The only exceptions are `src/web/main.tsx` (`./index.css`, `./App`), which carry eslint-disable comments. Also use `useAppDispatch`/`useAppSelector` from `@store/store-helper`, never raw `useDispatch`/`useSelector`.

**State (three Redux slices, `src/store/`):**

- `vault` — the CV facts: `profile`, `links[]` and dynamic `sections[]` (each with `type`, `title`, `items[]`; each item has `fields`, `bullets[]`, `tags`, `shouldShow`). Defined by the `runtypes` schemas in `custom-types/vault-types.ts`. All edits go through the reducers in `store/vault/vault-slice.ts`. Skills reuse the item model: a group is an item (`fields.category`) whose `bullets` are the skills (`text` = name, `rating`).
- `cvData` — only `metaData` and `style` of the current CV file.
- `app` — UI state: page structure (section ids per `fullWidth`/`left`/`right` column; the ids `personalInfo`/`contactInfo` are the header, anything else is a vault section id), column widths, selected editor page, and the `shouldApplyChanges` / `shouldDiscardChanges` / `shouldAddNewItem` flags. `useSyncStructure` (mounted in `App`) keeps the structure consistent with the sections via `reconcileStructure`.

**Variants (CV-37).** `VariantSchema` (`custom-types/variant-types.ts`) holds tone, page limit, column layout, per-item `selection` (hidden items, order, emphasis, per-bullet visibility and wording) and `style`; hiding never touches the vault. `render(vault, variant)` (`shared/variant/render.ts`) is the pure function that resolves them into the document to draw. `store/variants` holds the list and the active one. Item visibility belongs to the active variant (the eye toggles in the editors and the Variants page write `selection`); the preview draws `render(vault, activeVariant)`, and `Item.shouldShow` in the vault is no longer used. The active variant's `layout` and `style` mirror `app.structure` and `cvData.style`: `activateVariant` loads them into the editor on switching, `useSyncActiveVariant` writes edits back. Emphasis ("Highlight" on the Variants page) draws the item's title lines bold.

**Template (CV-39).** The default page is the UK single column (`singleColumnLayout`: header, then every section full width); `twoColumnLayout` is the older two-column look. Both are buttons on the Page Structure page. The preview (still MUI) draws `render(vault, {...activeVariant, layout: app.structure})`, so the preview components take `RenderedSection`, not vault sections; sections the layout does not place are put in the left column by `render`. Date format defaults to `MMM YYYY`; the optional right-to-work line is `profile.rightToWork` shown when `style.shouldShowRightToWork`. Items use `breakInside: avoid`; the page forces black on white and `inherit` link colour so the app's global CSS does not leak in.

**Pagination (CV-40).** The preview measures itself: `usePagination` (`preview-page/use-pagination.ts`) reads the elements marked `data-cv-block` (`CvBlock`, `CvTypography pageBreak`, bullets; `data-cv-keep` = stay with the next block, e.g. headings) and feeds them to the pure `shared/layout/paginate.ts`, which pushes a block that would cross a page end to the next page and returns the page count and where pages start. The preview shows dashed `Page N` markers (hidden when printing) and a status line / warning against `variant.pageLimit` (1 or 2, set on the Variants page). The same blocks carry `break-inside: avoid` for printing. `style.paperMargin` now sets the paper padding (`PAPER_MARGIN_MM`).

**Fit numbers (#88, #90).** `shared/layout/fit-metrics.ts` `computeFitMetrics` turns the measured heights into `usedPercent` and `linesOver` (line height measured from the first bullet; used height = bottom of the last block, because the paper has a one-page minimum height). `usePagination` also returns `breakLabels` (what each page starts with). `PreviewPage` stores them in `app.fit` for the top bar chip and shows the overflow banner with actions (Auto-fit, Allow 2 pages, Undo auto-fit when it cannot fit).

**Hide to fit (#89).** `ItemSelection.relevance` (0-100, set by `applyProposal` from the tailor proposal) ranks items; `shared/layout/hide-candidates.ts` (`rankHideCandidates`, `pickItemsToHide`) lists the least relevant first (unscored = 50, later items first, summary never) and the workspace `FitPanel` (page inspector, shown while it overflows) ticks items hidden in the variant with the lines each saves, or hides the least relevant until it fits. Auto-fit itself still only changes spacing, margins and font (it does not hide). "Ask AI to pick what to hide" is not built.

**Export dialog (#91).** The top bar's "Export PDF" opens `workspace/export-dialog.tsx`: it saves the variant, asks the server for the real PDF (same path as before), shows it in an iframe and lists the checks from the pure `shared/export/export-checks.ts` (`exportChecks`: fits, contact details present, selectable text, no photo/DOB, hidden items; `suggestFileName`). Optional "also save JSON". Not built: checks for flagged rewordings / uncovered requirements (the tailor result is not stored anywhere yet) and "mark as applied after export" (use the Mark as applied button).

**Auto-fit (CV-41).** `shared/layout/fit.ts` is a pure stepper (`startFit`, `stepFit(input, state, measuredPageCount)`, `describeFit`): `fit` mode shrinks spacing, then margins (floor 12 mm), then font size (body text floor 9.5 pt), then hides items from `hideCandidates` (empty until tailoring provides relevance); `fill` mode grows spacing then font size while it still fits. It never leaves the floors/ceilings. `useAutoFit` holds the state and the preview does the loop: draw with `tuning` (CSS vars `--cv-spacing`/`--cv-font-scale` on the paper, padding from `marginMm`, gaps via `spaced()`), wait until `usePagination` has measured exactly that drawing (`pagination.key === layoutKey`), step, repeat. The result is saved as `variant.tuning` (so the PDF can reproduce it); `variant.isAutoFit`/`fitMode` are set on the Variants page. Pagination/fit need a real browser to be exact; tests fake the layout.

**Drag and drop (CV-42).** Section placement (`section-placement/`) keeps its pure helpers in `section-placement-utils.ts` (`moveBetweenColumns` while dragging, `reorderInColumn` on drop) and has a keyboard sensor. Items and bullets are reordered per variant on the Variants page (`variant-section-items.tsx`): a drag handle (pointer or keyboard) plus up/down buttons; the order is stored as `order` in `ItemSelection`/`BulletSelection` (`computeOrders`) and `render` applies it. Dragging is not in the preview itself.

**PDF (CV-43).** `POST /api/pdf {variantId}` (server, `pdf/pdf-renderer.ts`, behind the `PdfRenderer` interface so routes are tested with a fake) opens the web app's print-only route `/?print=<variantId>` in headless Chromium via Playwright and returns the A4 PDF (text layer, background, `preferCSSPageSize`). The route is `pages/print-page/print-view.tsx`: it loads the saved vault + variant from the API, draws `PreviewPage isPrintView` (no editor, no markers, saved `variant.tuning` applied instead of re-running auto-fit) and sets `@page` margin itself, so every printed page has the margin and the paper is just the text area. It signals `data-cv-ready="true"` (or `data-cv-error`) for the renderer to wait on. The PDF is of the _saved_ variant, so the PDF button saves first. The old `react-to-print` Print button was removed in PR chore/remove-old-print (revert that commit to bring it back).

**AI (CV-45).** `server/ai/`: `ClaudeAiClient.generate({promptName, input, schema})` asks Claude (SDK `@anthropic-ai/sdk`, model `ANTHROPIC_MODEL`, default `claude-opus-5-5`, adaptive thinking) for a JSON object, checks it with a runtypes schema and, when wrong, sends the problem back and retries (3 attempts), else throws `AiError` (`not_configured|timeout|api_error|refused|truncated|invalid_output`). Prompts are files in `server/ai/prompts/*.md` (`loadPrompt`). The key comes from `.env` (git-ignored; copy `.env.example`), is only read on the server (`readAiConfig`), is scrubbed from every error (`redact`), and the browser only learns whether one is set (`GET /api/ai/status`). Tailoring (CV-46): `POST /api/ai/tailor {jobAd, tone}` runs `ai/tailor.ts` — call 1 extracts requirements (`extract-requirements.md`), call 2 (`propose-selection.md`) gets requirements + tone + the CV's ids/text/tags (never the profile/contact details) and returns per-item relevance/include/highlight, per-bullet include and optional rewrites (only as alternative wordings), a draft statement and the gaps; `sanitiseProposal` drops entries for ids not in the CV and clamps relevance. Types in `custom-types/tailor-types.ts`; fixture adverts in `fixtures/job-ad-*.txt` (one tries prompt injection). `AiError` codes map to 503/504/422/502. Guardrails (CV-47): `shared/ai/guardrails.ts` `checkRewrite(rewrite, sources)` flags every number, technology/proper-noun not present in the source text (bullet, its item's fields, sibling bullets, tags); `sanitiseProposal` always recomputes `bullet.flags` (the model's own are ignored) and `statementFlags` (against the whole CV) and adds a warning; `canAutoAccept(flags)` is false for anything flagged. Review UI (CV-48): the "AI assistant" editor page (`pages/ai-page/ai-assistant.tsx`, deliberately self-contained so it can be moved in a redesign): paste an advert, pick tone/page limit, Analyse (`ApiClient.tailor`, only if saved and a key is set; the page says what is sent to Anthropic), then per-item/per-bullet accept checkboxes with the diff against the current variant, flagged rewordings unticked, gaps and warnings, the draft statement (copy only). `shared/ai/apply-proposal.ts` (`defaultDecisions`, `describeItemChange`, `applyProposal`) turns the accepted part into a NEW variant (copy of the active one, items ordered by relevance) plus alternative wordings added to the vault bullets (text never changed); `insertVariant` adds it. Nothing is applied before "Create variant". Remember this sends CV text to Anthropic when Claude is the provider. **Providers (#76):** `AI_PROVIDER=claude` (default; paid) or `ollama` (free, local, `ollama-client.ts`, plain HTTP to `OLLAMA_URL` which must be this machine so nothing leaves it; JSON mode and `OLLAMA_NUM_CTX`, default 16384, because Ollama's own context is too small for a CV). `ai-provider.ts` `createConfiguredAi` picks one; both use the same `ClaudeAiClient` check-and-retry loop (name is historical) with a different sender, so the Claude code is untouched and can be switched back to in `.env`. `GET /api/ai/status` returns `{isConfigured, provider}` and the AI page words its privacy notice accordingly.

**Scrubbing (#81).** `shared/ai/redact-personal.ts` (`scrub`, `restore`) swaps the vault `profile` + `links` for placeholders (`[Candidate Name]`, `[First Name]`, `[Email]`, `[Phone Number]`, `[Address]`, `[Right To Work]`, `[Link n]`). `ClaudeAiClient.generate` does it for every provider when the request has `personal` (`tailor` always passes it): the sender wrapper scrubs system + all messages (retries too) and restores the raw reply before parsing; a placeholder the model changed stays and is reported through `onWarning` (shown as a tailor warning). Not scrubbed: employer/school names, dates, wording.

**Saving (CV-38).** `store/persistence/` holds the typed `api-client` (responses checked with the shared schemas), the pure `persistence-logic` (what changed since the last save), the slice, and `loadFromServer`/`saveToServer`. Nothing is saved automatically: the Save button writes what changed (vault, changed variants, deletions); `SavedState` is the text last known to be on disk. If the saved data cannot be read (`error`) or the server is down (`offline`), saving is blocked so the default empty CV never overwrites a file. In dev, the sample CV is shown (unsaved) when nothing is saved yet. `usePersistence` (mounted in `App`) loads at start and warns before closing with unsaved changes.

**Files and migration.** The saved file is `CvFile` = `{metaData, vault, style}`. `migrateCvFile` (`store/vault/migrate-vault.ts`) reads every supported format: older legacy files (`{metaData, data, style}`) are converted, vault files go through a version chain (`VAULT_MIGRATIONS`, add a step and bump `CURRENT_VAULT_VERSION` when the format changes). Never read a CV file without it.

**Editor draft/apply pattern.** Editors edit a _local draft_ built with `useVaultDraft`: a `useReducer` over the same `vaultReducer`, so editors use the exact reducers the store uses. `useSectionDraft` adds the item operations for item-based sections. Apply/Discard/Add buttons live in the footer and communicate through the one-shot boolean flags in the `app` slice: the button sets the flag, the editor reacts in a `useEffect`, runs the callback and resets the flag. A change of the stored data (import, discard) resets the draft; visibility toggles are also written to the store at once and use `skipNextReset` so other unapplied edits survive. Editor pages are chosen by section `type` in `editor-page.tsx`; the preview does the same in `preview-page.tsx`. Types without a special layout (projects, certifications, publications, volunteering, custom) use the generic editor/preview (`title`, `subtitle`, `location`, dates, `description`, bullets). The Sections page (`editor-sections.tsx`) adds, renames, reorders and deletes sections and applies at once (no draft). Tags and alternative wordings are edited in `item-metadata/item-extras.tsx`, a collapsed panel that only mounts when opened (keeps the editor fast).

**Preview** (`pages/preview-page/`) reads the vault and lays parts out according to `app.structure`. Drag-and-drop of parts between columns is in `editor-page/section-placement/` using `@dnd-kit`. Typography/fonts/colors come from `custom-styles/` and `style`; shared text rendering goes through `components/cv-typography*`.

**Import/export** (`hooks/use-import-export-json.ts`): export downloads a `CvFile`; import goes through `parseCvFileText` (which migrates). In dev only (`import.meta.env.DEV`) the app starts with the fake `fixtures/sample-cv.json`; the dynamic import is stripped from production builds.

**Server** (`src/server/`): `buildServer({storage})` in `app.ts` builds the API (`/api/health`, `/api/vault`, `/api/variants[/:id]`); `main.ts` only wires config and starts it on `127.0.0.1`. All data access goes through the `CvStorage` interface (`storage/cv-storage.ts`); `FileCvStorage` keeps `vault.json` and `variants/<id>.json` in `DATA_DIR`. Rules it enforces: every read and write is validated with the shared schemas (reads of old files go through `migrateCvFile`); writes are atomic (temp file + rename) and serialised per file; the previous readable version is kept as `.bak`, an unreadable file is moved to `.corrupt-<time>` and never replaces the backup; a corrupt file is reported (HTTP 500 `corrupt`) and never treated as empty; variant ids are whitelisted (`[A-Za-z0-9_-]{1,64}`) because they become file names; requests with a non-local `Host` or `Origin` are refused with 403. Variants are validated with `VariantSchema`.

**Data repo (#73).** `data/` can be its own private git repo (`cv-builder-data`; `git clone` it as `data/`). When `DATA_DIR` has its own `.git`, `VersionedCvStorage` (`server/backup/`) wraps the storage and `BackupService` commits after every save/delete ("Save: vault", "Save: variant x"). A git failure never blocks a save; it is reported by `GET /api/backup` (`isEnabled`, `hasRemote`, `unpushedCommits`, `lastError`). Pushing is always explicit: `POST /api/backup/push` or `pnpm data:push`. A parent repo never counts (only `DATA_DIR/.git`), and without git everything works as before.

**Applications (#74).** `ApplicationSchema` (`custom-types/application-types.ts`) is one job application: company, role, `appliedAt`, `status` (`applied|interview|offer|accepted|rejected|withdrawn`), a `history[]` timeline, optional job link/description/notes and `submitted` = the CV exactly as sent (`render(vault, variant)` output + the variant + tuning, deep-copied so later edits never change it). Pure helpers in `shared/application/application-utils.ts` (`createApplication`, `updateApplication`, `isNoReply` = still Applied after 30 quiet days, derived never stored, `formatDay`). Stored by `CvStorage` as `applications/<id>/application.json` + `cv.pdf` (PDF written first; delete moves the folder to `<id>.deleted`). Routes: `GET/POST /api/applications`, `GET/PATCH/DELETE /api/applications/:id`, `GET .../:id/pdf`. `POST` renders the PDF of the _saved_ variant and stores nothing if that fails. UI (`pages/applications-page/`): "Mark as applied" in the app bar (saves first via `hooks/save-active-variant.ts`, then a dialog) and `ApplicationView` at `/?application=<id>` (status dropdown asks for a date and note, timeline, the PDF that was sent, notes, "Create new variant from this", delete).

**Applications list (#75).** `/?applications` (`ApplicationsPage`, linked from the app bar): one row per application (company, role, status chip, date applied; "No reply" chip derived), a summary line, a search box and status chips. The pure logic is `shared/application/application-list.ts` (`arrangeApplications` = search + filter + sort, `summariseApplications`, `viewToQuery`/`queryToView`). The search/filter/sort state lives in the address (`replaceState`), and the application page's back link uses `history.back()` when it came from the list, so the same search is shown again. A damaged application is shown as a warning row (never hidden by a filter) and a failed load shows the error, never an empty list.

**Workspace (design B, #92/#93/#94).** `App` shows `pages/workspace/workspace.tsx`: `TopBar` (variant switcher, fit chip, save state, Tailor, Export PDF, Mark as applied), `ToolRail` (Vault, Variants, Tailor, Applied; `app.tool`), and for "Variants" the canvas (`PreviewPage`) plus `Inspector`. Clicking an item or section on the paper (`data-cv-item` / `data-cv-section`) sets `app.selectedBlock`; the inspector then shows that item's variant settings (shown, emphasise, bullets via `ItemBullets`) with an "In vault" tab, or, with nothing selected, page limit, layout, auto-fit and a sections list. "Tailor" still shows the old `AiAssistant` inside the frame until #97. **Vault (#96):** `workspace/vault-page.tsx` = tree of sections and items (click an item to see "Where this item appears": per-variant eye) + the old per-page editors (`useEditorPages()` in `editor-page/editor-pages.tsx`, with the shared-fact warning and the Apply/Discard footer) + Settings pages + JSON import/export. The old `EditorPage` component still exists (used by tests) but is no longer mounted in the app. The design is the artifact `6247ec72-64bc-4104-8ba8-4ca29ddee414` (B1-B11); open issues are labelled `design-b`. Chat (#49) comes last; Compare (B9) was dropped.

**Personal data:** the real CV goes in `data/` (git-ignored, as is `cv-export.json`); never commit it. `data.example/` shows the layout and `fixtures/` holds fake data for tests. Older real exports are handled by the migration.
