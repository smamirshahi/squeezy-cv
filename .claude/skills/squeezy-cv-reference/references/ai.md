# ai: AI, send-to-AI, scrubbing, chat, import, AI settings

Moved out of CLAUDE.md. Check the code before trusting a detail; file names here can lag behind.

**AI (CV-45).** `server/ai/`: `ClaudeAiClient.generate({promptName, input, schema})` asks Claude (SDK `@anthropic-ai/sdk`, model `ANTHROPIC_MODEL`, default `claude-opus-5-5`, adaptive thinking) for a JSON object, checks it with a runtypes schema and, when wrong, sends the problem back and retries (3 attempts), else throws `AiError` (`not_configured|timeout|api_error|refused|truncated|invalid_output`). Prompts are files in `server/ai/prompts/*.md` (`loadPrompt`). The key comes from `.env` (git-ignored; copy `.env.example`), is only read on the server (`readAiConfig`), is scrubbed from every error (`redact`), and the browser only learns whether one is set (`GET /api/ai/status`). Tailoring (CV-46): `POST /api/ai/tailor {jobAd, tone}` runs `ai/tailor.ts` — call 1 extracts requirements (`extract-requirements.md`), call 2 (`propose-selection.md`) gets requirements + tone + the CV's ids/text/tags (never the profile/contact details) and returns per-item relevance/include/highlight, per-bullet include and optional rewrites (only as alternative wordings), a draft statement and the gaps; `sanitiseProposal` drops entries for ids not in the CV and clamps relevance. Types in `custom-types/tailor-types.ts`; fixture adverts in `fixtures/job-ad-*.txt` (one tries prompt injection). `AiError` codes map to 503/504/422/502. Guardrails (CV-47): `shared/ai/guardrails.ts` `checkRewrite(rewrite, sources)` flags every number, technology/proper-noun not present in the source text (bullet, its item's fields, sibling bullets, tags); `sanitiseProposal` always recomputes `bullet.flags` (the model's own are ignored) and `statementFlags` (against the whole CV) and adds a warning; `canAutoAccept(flags)` is false for anything flagged. Tailoring is per section (#320): analyse the advert once (`/api/ai/analyse`), then score each section (`/api/ai/score-section`). The whole-CV tailor route, the Tailor page and `apply-proposal` were removed (#403).

**Send to AI dialog.** Every request that sends text to an ONLINE model is held back by `gateAiFetch` (`web/store/persistence/send-gate.ts`, the default fetch of `createApiClient`; tests that pass their own fetch skip it): the server is asked the same route with the header `x-ai-preview: 1` (`aiFor` in `app.ts` returns `createRecorder` from `server/ai/send-preview.ts`, which records the masked messages, throws `PreviewStop` and the error handler answers `{provider, calls, terms, suggestions}`; works without a key), `SendToAiHost` (`workspace/send-to-ai-dialog.tsx`, mounted in `App`) shows them, and only "Send" makes the real request with the body field `masking` (`Masking` in `custom-types/masking-types.ts`: `custom` = text the user selected with a kind company/school/person/other, `skip` = automatic masks switched off). `maskedClient` adds it to `request.personal.masking`; `scrub` gives custom text `[Company n]` (numbering continues after the vault's employers), `describeMasking` counts what is replaced and `suggestMasks` finds other emails, links and phones. The dialog shows the JSON payload as an outline (`shared/ai/readable-text.ts`, display only; "Show exact text" shows the sent text); a selected phrase must appear in the sent text to match. A local provider (`isOnline` false) gets no dialog. Own masks can be remembered in `localStorage` `squeezy-cv-always-mask`; `withOneApproval` makes a loop (score all sections) ask once. There is deliberately no "don't ask again for N minutes". **Groq models** change; the list is <https://console.groq.com/docs/models> (default `openai/gpt-oss-120b`; Llama 3.x entries marked Contact Sales return 404 on a normal key).

**Scrubbing (#81).** `shared/ai/redact-personal.ts` (`scrub`, `restore`) swaps the vault `profile` + `links` for placeholders (`[Candidate Name]`, `[First Name]`, `[Email]`, `[Phone Number]`, `[Address]`, `[Right To Work]`, `[Link n]`). `ClaudeAiClient.generate` does it for every provider when the request has `personal` (`tailor` always passes it): the sender wrapper scrubs system + all messages (retries too) and restores the raw reply before parsing; a placeholder the model changed stays and is reported through `onWarning` (shown as a tailor warning). Not scrubbed by default: employer/school names, dates, wording. **Employer and school names (#133, #271):** always masked now (no checkbox and no `/api/ai/privacy`; `AiRegistry.isMaskingOrganisations()` is always true; an old `maskOrganisations` in `.ai-settings.json` is ignored). The Settings page says masking is best-effort and not guaranteed. `personalOf(vault, true)` `personalOf(vault, true)` adds `organisations` (`organisationsOf`: `company` of experience items, `institute` of education items, once each) to `PersonalData`, so `scrub` also swaps them for `[Company n]` / `[School n]` (longest first; also the name without its Ltd/Inc/LLC ending; names under 3 characters are skipped) and `restore` puts the full name back; a placeholder the model changed is reported through `onWarning` like the others. Used by tailoring, its request preview and chat; not by import (the pasted text is the data) or hide (labels are job titles, no vault is read). Dates and wording are still sent. **Automatic masks of what the text contains:** `withDetectedMasks(text, data)` (`shared/ai/redact-personal.ts`) adds `PersonalData.detected` = emails, links and phone numbers found in the text being sent that the profile does not list; they are hidden as `[Link n]` (numbering continues after the profile's links), `[Email n]`, `[Phone n]` without a click, shown in the Send to AI dialog like the other automatic masks (switch off with `masking.skip`). Used by `withScrubbing` (real send) and the recorder (preview); skipped when there is no profile (an import: the text is the data). Dates and year ranges ("2018 - 2021") are never taken for phone numbers. Schools, universities and colleges are `[Institution n]` (the kind key is still `school`).

**Chat (#49, part 2).** Rail tool "Chat" = the canvas plus `workspace/chat-panel.tsx`. The user types a request; `POST /api/ai/chat {message, context, history}` (`server/ai/chat.ts` `chat`, prompt `chat-edit.md`, task `chat` in the provider chooser) sends the saved CV with short ids (`s1`, `i2`, `i2.b1`, never the profile; scrubbed like tailoring) plus how the job is now (`shared/chat/chat-context.ts`), and gets `{reply, operations, warnings}`. The typed operations (`custom-types/chat-types.ts` `OperationSchema`: hideItem, emphasiseItem, moveItem, moveSection, hideBullet, useWording, rewriteBullet, setTone, setPageLimit) are made from the model's loose answer by `toOperations` (names matched loosely, short or real ids, unknown ids/operations dropped with a warning, `useWording` only for a wording that exists, tone/page limit checked, max 20, rewording flags recomputed with `checkRewrite`, the model's own never used). The panel lists them in words (`describeOperation`) with checkboxes, flagged rewordings unticked; "Apply n selected" runs `operationsToActions` (`store/chat/operations-to-actions.ts`: each operation worked out against a simulation of the reducers, so several moves add up; the same actions as manual edits, a section move also writes the template's layout) inside `batch(...)` = ONE undo step, and the message offers Undo while it is still the last step. Nothing is applied before approval; a rewording only adds an alternative wording to the vault bullet (text never changed). `setTone` was added to the slice. Tried with llama3.1 (CPU, ~3 min a turn): simple requests (hide an item, move a section) give valid operations; compound or ambiguous ones ("shorten my current role's first bullet and make the tone formal") made it ask a question and drop an operation, so the prompt says to use `rewriteBullet` to shorten and to give one operation per requested change; a hosted model is expected to do better. Not built: operations that add or edit facts (by design), streaming replies (still open, #136), a conversation shared between browsers. **Memory (#136):** `workspace/chat-memory.ts` keeps the conversation of each job in the browser's `localStorage` (`squeezy-cv-chat:<jobId>`, newest 40 turns; never in the data folder or data repo), reloaded when the panel opens or the active job changes; stored operations are re-checked with `OperationSchema`, an applied turn never offers Undo again after a reload, and "Clear conversation" forgets it.

**AI setup (#99).** the rail's "Settings" button opens `workspace/ai-settings-dialog.tsx` (`AiSettingsHost` in `App`, opened from anywhere with `openAiSettings(task?)` from `ai-settings-event.ts`; "Settings…" next to an AI action opens it on that task; left: All tasks / each task / set up the providers, middle: `AI_TASK_DESCRIPTIONS`, what is sent and masked, set-up and Ollama install steps, right: radio buttons saved at once; the old `/settings` address opens it and goes back to the apply page) lets the user choose the provider per task (#102) and shows what is sent / masked / never sent. "All tasks" sets every task; a task that differs from the most common provider is marked Overridden. **Providers per task (#102):** `shared/ai/providers.ts` lists providers (`AI_PROVIDER_INFO`: label, online/offline, recipient, detail) and tasks (`tailor`, `import`, `hide`). `server/ai/ai-registry.ts` `AiRegistry` holds a client per provider that is set up (`createAiClients`: Claude needs a key, Ollama always) and the choice per task: the default is `AI_PROVIDER`, `PUT /api/ai/choice {task: provider}` overrides it (refused with 400 `provider_unavailable` for a provider that is not set up) and `FileAiSettings` remembers it in `.ai-settings.json` (git-ignored, `AI_SETTINGS_FILE`; no secrets, keys stay in `.env`). The AI routes ask `registry.forTask(...)`; `GET /api/ai/status` still has tailoring's `isConfigured`/`provider` and adds `providers` and `choice`; the web uses `taskProvider(status, task)` so every privacy notice names the provider chosen for that task (`info.recipient`). Tests and older wiring can still pass one `ai` + `aiProvider` to `buildServer` (wrapped by `AiRegistry.single`). **Gemini and Groq (#85):** `AI_PROVIDER=gemini|groq` or just keys (`GEMINI_API_KEY`, `GROQ_API_KEY`, optional `*_MODEL`, `*_BASE_URL` which must be https or this machine) make them appear in the chooser. `server/ai/hosted-clients.ts` has the plain-HTTP senders (`createGeminiSender`: key in the `x-goog-api-key` header, system instruction, JSON mime type, roles user/model; `createGroqSender`: Bearer key, OpenAI-style messages, `json_object`); both use the same `ClaudeAiClient` check-and-retry loop, scrubbing (so no profile data in the request body: asserted on the raw body in `hosted.test.ts`), the same `AiError` codes (429/401/5xx and network problems -> `api_error` with a readable reason, `MAX_TOKENS`/`length` -> `truncated`, safety -> `refused`, no answer -> `timeout`) and `redact` for the key. Free tiers may train on prompts: `AI_PROVIDER_INFO[..].warning` is shown in AI setup and `.env.example` recommends Ollama for anything sensitive; the notice also says employer names, dates and wording can still identify a person.

**AI import (#101).** "Paste CV text, AI sorts it" (first-run screen and the Vault tree): `POST /api/ai/import {text}` (`server/ai/import-cv.ts`, prompt `import-cv.md`) returns `{vault, warnings}`. The model answers in the loose `RawImportSchema` (`custom-types/import-types.ts`); the pure `shared/vault/import-from-text.ts` (`importToVault`) gives it ids, turns dates into ISO and warns about every name/email/phone/bullet that is not in the pasted text (possible invention); `mergeIntoVault` adds the result to the existing vault without overwriting (empty profile fields filled, items into the first section of the same type, links deduped by URL). No scrubbing: the text is the personal data, so the dialog warns that Claude sends all of it to Anthropic (Ollama keeps it local). Tried end to end with Ollama (llama3.1, ~3.5 min on CPU; llama3.2:3b is faster but weaker) on `fixtures/messy-cv.txt`: small models omit `bullets` (now optional), fill unknown fields with `""` (dropped), leave `2013-2016` in `startDate` (split), add junk profile keys (only known keys kept) and can be pulled by an injected line (prompt rule + a warning when the text contains "ignore previous instructions"). `fixtures/messy-cv-model-answer.json` is a recorded real answer used by `import-messy.test.ts`. Nothing is added until the user confirms, and nothing is saved until Save. **PDF (#197):** the dialog also takes a PDF (Choose PDF / drop): the browser posts the raw bytes (`Content-Type: application/pdf`) to `POST /api/import/pdf` (`server/pdf/extract-pdf-text.ts` `extractPdfText`, `unpdf` is a runtime dependency now), which answers `{text, pages}` and the text goes into the editable box; nothing is sorted or sent to an AI until "Sort it". In memory only, never written to disk. Limits `MAX_IMPORT_PDF_BYTES` (5 MB, also Fastify's body limit for that parser) and `MAX_IMPORT_PDF_PAGES` (20) in `import-types.ts`; the header `%PDF-` is checked, not the extension. Error codes (`PdfTextError`): `not_pdf` (400; 415 for another content type), `too_large` (413), `too_many_pages`, `encrypted`, `no_text` (scan; no OCR), `text_too_long` (over `MAX_IMPORT_LENGTH`) as 400. Test PDFs come from `fixtures/make-test-pdf.ts`.

**AI cost and default models (#551, #562).** `shared/ai/pricing.ts` holds the price list (`MODEL_PRICES`, dollars per million tokens, copied by hand from the providers' pages; `PRICES_CHECKED_ON` is the day), the estimate before a send (`estimateRequestCost`) and the real cost after (`actualCostUsd`). The server reports the tokens a request used in the response header `x-ai-usage` (`AI_USAGE_HEADER`); `gateAiFetch` logs it (`store/persistence/ai-usage-log.ts`, browser storage only) and the "Cost and usage" page of AI settings shows the log. Claude defaults per task: Haiku for hide/place, Sonnet for the rest (`CLAUDE_TASK_MODELS` in `shared/ai/providers.ts`; `ANTHROPIC_MODEL` overrides all); effort per prompt (`PROMPT_EFFORT`, low for the small mechanical prompts, medium otherwise, never high). The default model is therefore `claude-sonnet-5-5`, not Opus. **Keeping the prices right:** `pricing.test.ts` fails when `PRICES_CHECKED_ON` is older than 90 days; the workflow `.github/workflows/ai-prices.yml` runs `scripts/check-ai-prices.ts` on the 1st of every month (`shared/ai/price-check.ts` decides) and opens, or adds to, one issue labelled `ai-prices` when a model's price is no longer on its provider's page. Then: open the pages, update `MODEL_PRICES` and `PRICES_CHECKED_ON`, add a changelog line, release. Nothing is updated automatically.
