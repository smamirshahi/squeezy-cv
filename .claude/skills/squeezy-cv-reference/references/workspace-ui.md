# workspace-ui: workspace, rail, panels, outline, theme, canvas, style settings, states

Moved out of CLAUDE.md. Check the code before trusting a detail; file names here can lag behind.

**Workspace (design B, #92/#93/#94).** `App` shows `pages/workspace/workspace.tsx`: `TopBar` (job switcher + template dropdown + New job, fit chip, save state, Export PDF, Mark as applied), `ToolRail` (see "Apply and Applications"; `app.tool`), and for "Jobs" the canvas (`PreviewPage`) plus `Inspector`. Clicking an item or section on the paper (`data-cv-item` / `data-cv-section`) sets `app.selectedBlock`; the inspector then shows that item's job settings (shown, emphasise, bullets via `ItemBullets`) with an "In vault" tab, or, with nothing selected, layout, auto-fit and a sections list. **Vault (#96):** `workspace/vault-page.tsx` = tree of sections and items (the right item panel is empty on purpose, #229: what a job shows is decided in the job, and a sent application is a frozen copy) + the inline item editor (`workspace/vault-item-editor.tsx`, #96: click an item in the tree; fields from `shared/vault/item-fields.ts` `fieldSpecsFor`, month inputs stored as ISO days with a Current checkbox for no end date, bullet cards with canonical text, tags, Short/Long/Formal wordings, up/down, Ctrl/Cmd+Enter for the next bullet, `[`/`]` for previous/next item, remove with confirmation; field edits of experience/education/generic items wait in a local draft until Apply (Discard restores; #265; one input per line, start/end/Current share one line; unapplied drafts block navigation via `useUnappliedDraft`), while adding/removing items, skills and bullets go straight into the vault store; skills use the same editor with one row per skill: name, star level (optional, `No level` clears it, level name beside it), up/down, remove (no years: removed in vault version 3); **Track my level (#145):** `Section.tracksLevel` (optional; missing = on if any skill has a rating, `tracksLevels`) hides the level control and makes `render` leave `rating` out, while the stored ratings are kept; the summary keeps the old editor because it has no item list) + the old per-page editors for sections, Main Info etc. (`useEditorPages()` in `editor-page/editor-pages.tsx`, with the shared-fact warning and the Apply/Discard footer). Education items use `institute` (not `institution`); AI import maps the old key + Settings pages + JSON import/export. The old `EditorPage`, its app bar and side bar, `EditorPageButtons` and `useDownloadPdf` were removed; the editor tests render `VaultPage`. The design is the artifact `6247ec72-64bc-4104-8ba8-4ca29ddee414` (B1-B11); open issues are labelled `design-b`. Compare (B9) was dropped. Chat (#49) is built, see "Chat" below.

**States (#100).** `workspace/workspace-states.tsx`: `ConnectionBanner` (under the top bar when the server is offline or its data unreadable: Retry, and Download as JSON when there are unsaved changes) and `FirstRun` (over the canvas when `isVaultEmpty(vault)` from `shared/vault/is-vault-empty.ts`: Import JSON or add details by hand). The "paste CV text" button waits for #101.

**Outline (#95).** `workspace/outline.tsx`: the "Outline (O)" button (or the O key) on the canvas opens a tree of the active job's sections, items and bullets with eye, emphasis and up/down buttons (all keyboard-reachable), a live-region announcement of each move, and click-to-select on the page. It reuses the same reducers as the Jobs editor (`setItemOrders`, `setBulletOrders`, ...) and `moveSection`. Sections, items and bullets also have drag handles (dnd-kit, one `DndContext` per list, `SortableRow`/`useReorderSensors`/`getDropIndex` from `job-section-items.tsx`; keyboard: focus the handle, Space, arrows; `moveSectionTo` for sections, also across columns); the up/down buttons stay. Indent levels from the design are not built (and not needed: the levels are fixed).

**Applications side panel (#98).** In the list (`/applications`) a row click opens that application in a side panel (`ApplicationView isEmbedded`, same component as the full page `?application=<id>`, which the company link still opens); the list keeps its search and filters. The list has a row of status tiles (All, each status, No reply) with counts; a tile is also the filter (`ListView.status` may be `noReply`, derived with `isNoReply`/`countNoReply`, kept in the address as `status=noReply`).

**Theme and inspector (#94).** `custom-styles/theme.tsx`: `AppThemeProvider` (wraps every page except the print route, so the PDF is always the light default) holds light/dark (saved in localStorage `squeezy-cv-theme`, default = system), writes the design tokens as CSS variables (`--pn`, `--bd`, `--ac`, ... from artifact B1, `THEME_TOKENS`) and builds the MUI theme (IBM Plex Sans from `@fontsource`, self-hosted; sentence-case buttons; 4 px radius). `WORKSPACE_COLORS` are now `var(--...)` strings, so chrome colours follow the theme; use them (or `cssVar`) instead of hex in the app UI. The CV paper stays black on white. The rail has a Light/Dark button. Inspector bullets are cards (`ItemBullets isCard`): drag handle, eye, tags, Canon./Short/Long segment (a wording without text is disabled) plus the up/down buttons as keyboard alternative.

**Canvas shortcuts (#93).** `workspace/use-canvas-shortcuts.ts`: with an item selected on the page, H shows/hides it, B toggles emphasis, Alt+Up/Down moves it in its section, Escape deselects (ignored while typing). **Block toolbar (#93):** `workspace/block-toolbar.tsx` floats to the right of the paper at the height of the selected item (show/hide, emphasis, move up/down; positioned from the DOM rect inside the canvas, follows zoom and edits, stays in place while the item is hidden so it can be shown again). It shares `use-block-actions.ts` with the H/B/Alt+arrow shortcuts. Not built: a drag handle in the toolbar (reorder by dragging is in the outline and Jobs page). **Zoom and Tab:** `app.canvasZoom` (0.5-2, `setCanvasZoom`, keys + - 0, the `ZoomControls` top right of the canvas incl. Fit width). `ZoomFrame` (`workspace/canvas-zoom.tsx`) scales the page with `transform: scale` and resizes its layout box to the scaled size; the page itself is unchanged, and `use-pagination` divides its `getBoundingClientRect` numbers by `screenScale(paper)`, so page counts and fit numbers are the same at every zoom (e2e `canvas.e2e.ts` checks it). The paper is focusable (`data-cv-paper`, tabIndex 0, not in the print view): with it focused Tab / Shift+Tab select the next / previous item in reading order and let go at the ends (the keyboard is never trapped).

**Style settings (#157, design B14).** The Style part of the Design page (`editor-page/sections/editor-style-settings/`, `EditorTypography`) has no Apply step: a Page card (margin, date format, skill and bullet icon, right-to-work), `ColoursCard` (#283: `style.colors` = `text`, `secondary`, optional `accent`; three colour buttons side by side, each opens a popover with a quick palette (`COLOR_PALETTE`), a colour picker (`colour-area.tsx`: shade square + hue slider; pure `shared/style/color-convert.ts`) and a hex field; a valid colour is saved at once, below 4.5:1 on white an (i) tooltip next to the button explains it; `setColors`) and `TypographyTable` (5 rows: Name `headingLg`, Section heading `headingMd`, Item title `headingSm`, Body `bodyMd`, Small `bodySm`; sample at real size, size stepper over `FONT_SIZES`, Regular/Bold). The "Reset colours and text styles" button is in the page header (`resetTypography`: sizes, weights and colours; the Page card options stay). The schema still stores all 8 `typography` entries; `shared/style/resolve-style.ts` `resolveTypography(style)` (hook `useResolvedStyle`) is what everything draws: headline, bullets and icon take the Body size, text colour goes to every style except Small (secondary) and Section heading/icon/bullet markers/heading rule (accent, else text); `colorsOf` falls back to the old `bodyMd`/`bodySm` colours for a file without `colors`, so no migration; the colours inside `typography` are no longer used with an (i) tooltip per style (`STYLE_TOKENS[].where`); the right panel is `StylePreviewPanel` = `TemplateSample` (the user's vault in the template being edited; the earlier demo text, style names and hover fading were removed). The skill rating icons and level symbols use the resolved icon style (Body size, accent colour). `style.ratingIcon` (default `text`, first in the list) can be `text`: the level is shown as a word (`levelLabel`) when the template has no `skillDisplay`; skills are one per line unless the template has 2 columns. The Page card also has `style.sectionSpacing` (px, 0-40, default `GAP_PX.sectionTop`) and `style.hasHeadingLine` (default on), template-wide (#209; per-section styles no longer exist, old `sectionStyles` data is ignored). Pure helpers (`isValidHex`, `normaliseHex`, `contrastOnWhite`, `stepFontSize`) are in `shared/style/typography-utils.ts`. The default secondary colour is #555555 (#777777 fails 4.5:1).

**Middle area look (#205).** `MIDDLE_AREA_SX` (`workspace-tokens.ts`) is spread into the `sx` of the middle area of Vault, Templates and Job settings: grey page (`bg`), white bordered `Paper`s, white inputs with the `ib` border, amber warning. **Templates page (#210):** the clicked template card (`data-selected`) is the one `TemplateSample templateId` draws (the active template live, others as saved); only on the Templates tab.

**Job data and resizable panels (#159).** The "Job data" page (was "Meta Data", `EditorMetaData`) edits `metaData` of the CV file: job title, URL and the private, optional `opinion` (`JOB_OPINIONS`: want it, good match, optimistic, neutral, unsure, long shot; dropdown) and `notes`; not rendered and not sent to AI. `workspace/resizable-aside.tsx` wraps the vault tree (left) and the vault right panel, inspector and chat (right): drag the handle or use Left/Right arrows on it, double-click resets; width per side in `localStorage` (`squeezy-cv-panel-width:<side>`, 220-640 px, `panel-width.ts`). The outline drawer is not resizable. The style preview, the Tailor panels and the application panel use `ResizableAside` too (#206); the width is saved once per side. **Full height (#199):** `ResizableAside` stretches its wrapper and makes the panel inside it fill the height (`&& > *` sets `flex: 1 1 0`, outranking the panels' own `flex: none`), so a panel needs only its background, border and `overflow: auto`; e2e `sidebar-height.e2e.ts` measures the panel and handle bottoms against the window.

**Apply and Applications (#298).** Rail: Vault, Templates, Apply, Applications (always shown; `Workspace` also renders `/applications` and `/applications/<id>`, `ShellRoute`, no page reload). Apply = `ApplySidebar` (resizable left list: Job application `?view=details`, Template & content `?view=page`, Assistants Tailor `/tailor` and Chat `/chat/<job>`; entries that need a job are disabled while `isPlaceholder`). `job-details-page.tsx`: the first edit with no real job creates it (`createJob` + `setJobDetails`); the stand-in job is never edited. New optional `Job` fields: `url`, `location`, `workMode`, `employmentType`, `salaryMin/Max`, `salaryIsRange`, `expectedSalary`, `feeling`, `chance`, `stage` (`draft|ready`), `hiddenLinks`. Template & content: `TemplateBar` + canvas + `ContentPanel` (steps: header and links, then each section not removed; `JobContent only=`; layout and section order are template matters, removal of a section is `hiddenSections` via the bin in Arrange sections and `IncludeSectionButton`). Applications: `applications-page.tsx` has `CategoriesSidebar` (a filter over one table of unsent jobs from `GET /api/jobs` without an application, plus applications) and a right panel (`JobPanel` or `ApplicationView isEmbedded`). The e2e specs describe this layout and run in CI (#315, #360); unit tests are still paused.

**ATS score (#258).** Pure scoring in `shared/ats/ats-score.ts` (`scoreAts`: CV-only categories formatting/searchability/content, job-match categories hardSkills/softSkills/titleExperience from `job.analysis ?? variant.tailor.requirements` + `job.jobAd`; penalties and `ATS_WEIGHTS` live there, `fixList` groups issues into to-do lines, `snapshotOf`/`compareScans` keep and compare scans). UI in `workspace/ats/`: `use-ats.ts` (live score + the first and latest scan of each job in `localStorage` `cvb.ats.<jobId>`, shared through `useSyncExternalStore`; nothing in the vault or job), `ats-panel.tsx`, `score-ring.tsx`, `ats-help-dialog.tsx`. Desktop: `ApplySidebar` (default width 272) shows the panel under a divider; below a desktop `ApplySidebar` adds an `AtsTab` to the strip that opens `?view=ats` (route view `ats`; on a desktop that view is the CV page), where `Workspace` shows `AtsAside` (320 px beside the CV on a laptop, 500 px under it on a tablet in three columns, full screen on a phone with the CV kept laid out but hidden so the page count stays measured). The scoring is local and deterministic, so it is NOT marked as AI. The one AI part is "Suggest natural wording" (`ats-wording.tsx`, purple AI card + `AiButton`): `POST /api/ai/ats-wording {terms, reworded?}` (`server/ai/ats-wording.ts`, prompt `ats-wording.md`, types `custom-types/ats-wording-types.ts`, task `chat`, gated in `send-gate.ts`) sends the summary/description texts and the missing/differently worded keywords, recomputes flags with `checkRewrite` (terms in `reworded` count as known words, missing ones do not), and the ticked suggestions are written as `fieldText` of the job's item selection.

**Templates > Sections (#477).** Three tabs in the Templates nav: Template list, Sections, Design. `template-sections-page.tsx`: the section list (`SectionPlacement` with `selection`, so a row is a short selectable one and the drag handle stays; below a desktop the list moves under the properties as "Page layout and sections" and the header shows a dropdown), `TemplateSample` with `selectedPartId` / `onSelectPart` (outline and "Editing" tag via a style rule on `[data-cv-section]` / `[data-cv-header]`, screen only; header parts have `data-cv-header`), and `template-section-properties.tsx` (`SectionProperties` by id / section type: Personal Info, Contact Info, Work Experience and Education order, Publications, Skills icon, References). Arrows and the bin (remove from the template: the id leaves `app.structure`; "Add section to template" brings it back) are in the properties header. Design (`EditorTypography`) keeps only what is the same everywhere. New `Style` fields: `experienceOrder`, `educationOrder` (`newest|oldest`), `publicationOrder` (`newest|manual`), `publicationLinks` (`end|none`), `highlightOwnName`, `maxAuthors` (3, 6, `all`); `Profile.citationName` lives in the vault. `shared/variant/entry-order.ts` applies the order in `render` unless the job set an order by hand; `shared/vault/citation.ts` returns `CitationSegment[]` (bold, italic, link) drawn by `CvCitation`.
