# routing: hand-written routing and address map

Moved out of CLAUDE.md. Check the code before trusting a detail; file names here can lag behind.

**Routing (#198).** Hand-written, no router library (the app has one page shell and a handful of addresses; `react-router` would add a dependency and its own state for little). `shared/routing/routes.ts` is pure: `parseRoute(pathname, search)` / `formatRoute(route)` (inverse) and `legacyRedirect` (old `/?applications...`, `/applications/<id>`, `/?print=<id>` and `/` -> `/vault`, the home page, #455). Addresses: `/vault[/<section>[/<item>]]`, `/jobs[/<job>][?view=settings]`, `/templates[/layout|/style]`, `/chat[/<job>]`, `/settings` (`/ai` is read as the same), `/applications[?q&status&sort&dir]`, `/applications/<id>`, `/print/<job>` (the server's `PdfRenderer` opens it); anything else is `notFound`. `hooks/navigation.ts`: `navigate(route|url, {replace})` (pushState + an event), `useRoute()` (`useSyncExternalStore` over `popstate`), `onAppLinkClick` (plain left click navigates, modifier clicks keep the browser's behaviour; use it with a real `href` on rail items, tree items, tabs) and `useUnappliedDraft(isDirty)` (set by `useVaultDraft` when the draft differs from the store): while an editor holds one, `navigate` and Back ask `window.confirm` first. **The address is the source of truth.** `App` renders by route (`Workspace route` for the tools; the applications pages and the print page are separate and reached by a normal page load, so closing/leaving warns through the existing `beforeunload`). Workspace derives the tool from the route; `hooks/use-route-sync.ts` mirrors it into `app.tool` and clears the canvas selection, and keeps the **active job** in step both ways without a loop: `/jobs/<id>` and `/chat/<id>` activate that job, and when the active job changes by other means (switcher, new job, tailoring, delete) the address follows; whichever changed since the last run wins. `/jobs` and `/chat` without an id get the active job's (replace). `VaultPage` reads section and item from the address and mirrors the section into `app.selectedSectionInEditorPage` for the footer and old editors. `Workspace` shows `NotFound` (`workspace/not-found.tsx`) for an unknown job, vault section or item once the data has loaded (`persistence.status` is not `loading`), and sets `document.title`. Templates: `/templates` (list) and `/templates/<id>/design` (#212, #283: the template the Design page edits; `/templates/design` without an id is filled in with the active job's template by `replace`; an unknown id shows `NotFound`). `app.editedTemplateId` (set by `use-route-sync`, null = the active job's template) is the template that `app.structure`/`cvData.style` mirror: `useSyncActiveJob` loads its look when it changes (before any write, so one template's look never lands in another) and writes edits back with `setTemplateLook({templateId, ...})`; `editedTemplateSelector` and `restore` in `history.ts` follow it too, so undo puts the right look back and `TemplateScopeNote` names it. The templates page has `EditedTemplateSwitcher` and an Edit link on each card; the card clicked on the list is the one the Layout/Style links open. Rail items are `<a>` links, so tests use `getByRole("link")`.
